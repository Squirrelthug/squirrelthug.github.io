L.I.L.I.T.H. — Core System

v6 is a clean-slate rebuild, and it was designed in full before a line of it was written: a twenty-nine section specification, frozen after three adversarial review rounds, implemented exactly as written. It runs as a single PySide6 desktop application — not a service, not a browser tab. Speech arrives through a VAD-gated faster-whisper pipeline. A two-mode router decides whether a request is conversational, which owes the user audio in under three seconds, or an artifact, which is acknowledged immediately and handed to a background worker that reports back when it has something real to say. A Context Window Manager assembles exactly the context that request needs and nothing more. Every event and every mutation is logged. All six databases are SQLCipher-encrypted from the very first migration, so there is no moment in this project's history when a plaintext database exists.

Internally the shape is a strict one-way dependency, and CI fails the build when it is violated:

The UI never calls the backend. Every screen mutation arrives through a command bus that the backend drives, which is what allows one program to be voice-first and touch-first at the same time. And nothing that matters is mocked in the test suite — it runs against real SQLCipher databases, because the previous generation's mocked-database tests hid precisely the bugs that were most expensive to find later.

Design Philosophy

The Principles Behind the Work

Every architectural decision in this project is evaluated against a fixed hierarchy. These are not aspirational values — they are active constraints that govern tradeoffs.

01

Voice is the product

Everything else is secondary. Any feature that degrades the voice experience doesn't get built until the voice experience is right.

02

The foundation carries full weight

No shortcuts that close off future phases. The one-way layer boundary, a data layer encrypted from its first migration, and the command bus between backend and UI — these don't change. The models and interfaces that plug into them do.

03

Simplicity wins every tie

The developer has to be able to read, understand, modify, and debug any code in the system. Complexity without near-term value is the wrong choice, every time.

04

Privacy is a constraint, not a feature

No user data leaves the local system without explicit action and understanding. This is not a selling point — it is a precondition of the entire design.

05

Daily use is the feedback loop

The developer is the primary user. A feature that isn't in daily use isn't a real feature yet. The system has to earn its way into the workflow before it earns resources toward the next layer.

06

Pour the foundation knowing the building

Frame walls after the foundation cures, not before. The current implementation is small. The foundation is sized for what this becomes — not just what it is today.

Development Roadmap

Where This Is Going

v6 builds as fourteen sequential chapters. The order is not a feature wishlist — it is a dependency and risk ordering, arranged so the least certain assumptions get measured before anything expensive is built on top of them.

v5 · Archived

The Previous Generation

A working system, in real daily use, and the lessons that justified starting over anyway: security retrofitted too late to be structural, mocked databases hiding the bugs that mattered, and a foundation that had accreted rather than been designed. Archived in August 2026 so that v6 could begin from an empty directory. No v5 code crosses into v6 — only the understanding does.

Milestone 1 · In Progress

The Walking Skeleton

The smallest end-to-end voice loop worth using every day: microphone through VAD, speech recognition, reasoning, speech synthesis, speaker — with exactly one database and exactly one tool, a full-text recall over past conversation. In practice that is a voice memory journal: dictate a note, then ask about it days later and get a spoken answer. Six chapters carry it — foundation, voice I/O, the intelligence core, memory and the first tool, the frontend shell, then integration and daily dogfooding. Foundation & Skeleton is the chapter open now.

Gates · Before Anything Builds On It

Two Measured Bets

Milestone 1 ends at quantitative gates rather than a judgement call: a latency benchmark against the sub-three-second conversational budget, and a router dry-run against a hash-frozen hundred-utterance set with a committed misroute ceiling. A third floating gate tests encrypted-vector feasibility before anything is allowed to depend on vectors. Failing a gate changes the design — that is what they are for.

Phase 2

Foundation Hardening & Telemetry

A real telemetry database, a logging sanitizer with a strict no-plaintext boundary, crash recovery that quarantines a corrupt database and offers a restore instead of silently deleting it, and CI green on Linux, macOS and Windows in parallel.

Phase 3

Security & Key Management

The rest of the credential lifecycle — passphrase rotation, database relocking — and a merge-blocking gate on personal-information recall that will not let a build ship below 95% on names and 100% on emails and phone numbers.

Phase 4

Local Intelligence & Fallbacks

Local inference on machines that can carry it, through an Ollama adapter with GPU detection — and a visible indicator of which provider is actually answering, so the system never quietly pretends to be local.

Phase 5

The Custodian App Suite

First external data: Google OAuth through the system browser, contact and calendar sync mirrors, the people tools, and deep links that let a spoken answer navigate you to the record it came from. Read-only by audit — no write scope is ever requested from Google.

Phase 6

Calendar

Lilith's own calendar on top of the sync mirror: two event stores, echo detection so a synced copy of her own event is never mistaken for a conflict, agenda summaries, a read-only feed real calendar clients can subscribe to, and a cancel that cancels rather than deletes.

Phase 7

Onboarding, Extension & Final Freeze

A guided first run, a skills directory with deliberate enrollment friction — hash manifests, and an injection cap that rejects oversized input rather than quietly truncating it — the complete orb state machine, and then the freeze that makes v6 a finished thing instead of a permanent construction site.
