Frontend Layer
26Frontend Framework & Application ShellComplete▶

PySide6 6.11.1 (LGPL v3). Qt Signals/Slots is the event bus. All UI mutations go through a UICommandBus that the backend calls — the UI never calls the backend directly.

  • Framework: PySide6 6.11.1 (LGPL v3). ModernGL 5.x (MIT) for the orb via QOpenGLWidget. Qt Quick 3D dropped (GPLv3-only, incompatible with closed-source distribution).
  • Module dependency direction: UI layer → logic layer → data layer → platform layer. No circular imports. Backend never imports from UI modules.
  • UICommandBus: a QObject subclass that lives on the main thread. Exposes @Slot methods that the backend calls via QMetaObject.invokeMethod(..., Qt.ConnectionType.QueuedConnection). This ensures all UI mutations happen on the Qt main thread regardless of which thread the backend is on. 
    class UICommandBus(QObject):
    @Slot(str)
    def set_orb_state(self, state: str): ...
    @Slot(str)
    def append_message(self, json_payload: str): ...
    @Slot(str)
    def show_screen(self, screen_name: str): ...
  • Screen navigation: QStackedWidget as the central widget. Screens are named: "onboarding", "conversation", "contacts", "calendar", "settings". Navigation via UICommandBus.show_screen(name).
  • MainWindow: frameless or custom-framed window. Contains: OrbWidget (top or floating), QStackedWidget (content area), sidebar navigation.
  • Untrusted-skill indicator (answer time — §13/§29 skills trust surface): When a reply was generated with a user-enrolled (non-curated) skill injected, the shell displays a persistent indicator at answer time, following the §12 provider-indicator pattern: always visible while it applies, in the main application shell, never a toast, transient notification, or log-only signal. It is driven exclusively by the router's injection signal — the same signal that emits router.skill.injected with trust_source=user-enrolled — delivered over the UICommandBus (@Slot(str) set_skill_indicator(json_payload) carrying skill name, SHA-256 hash, trust source, and turn/task id); the UI never re-parses skill files or manifests to decide indicator state. Normative content requirements (not final copy): the indicator states that an unverified skill the user enrolled shaped this reply, and names the skill. Mode coverage: in text mode the affected answer message permanently carries an inline unverified-skill badge in the transcript, and the shell indicator is visible while that answer is the active turn; in voice mode — including voice-only turns with no artifact panel open — the indicator is shown on the session (conversation) screen at answer time, and that turn's transcript entry permanently carries the same badge, so the fact remains discoverable after the audio ends. Curated skills never trigger this indicator: it marks the trust-boundary crossing, not skill use in general — firing it for hash-pinned curated skills would train banner blindness and dilute the warning. router.skill.injected remains the audit record; a failure to render the indicator when the signal was sent is a §08-tested defect, not a soft-fail.
  • LGPL compliance: PyInstaller --onedir required (users must be able to replace Qt shared libraries). LGPL and GPL license texts in licenses/ folder. Qt attribution notice with clickable Qt source link in About dialog.
  • UCL events: user.screen.navigate (from_screen, to_screen)

Functional Requirements — Untrusted-Skill Indicator (EARS Format)

  • FR-STS-001: While an artifact response was generated with an injected skill whose trust source is user-enrolled, when that response is delivered to the user (first text render, artifact panel creation, or first handoff audio), the system shall display the untrusted-skill indicator, naming the enrolled skill.
  • FR-STS-002: The system shall render the untrusted-skill indicator as persistent shell or screen content visible without opening logs, menus, tooltips, hover states, or settings; a transient toast or notification shall not satisfy this requirement.
  • FR-STS-003: When a message shaped by a user-enrolled skill is written to the conversation transcript, the system shall permanently attach an unverified-skill badge (skill name and trust source) to that message in every transcript view.
  • FR-STS-004: While a turn is voice-only, when a reply shaped by a user-enrolled skill is spoken, the system shall display the indicator on the session (conversation) screen at answer time and shall attach the badge to that turn's transcript entry.
  • FR-STS-005: The system shall derive indicator state exclusively from the router's injection signal delivered over the UICommandBus; the UI shall not read skill files or manifests.
  • FR-STS-006: Where the injected skill's trust source is curated, the system shall not display the untrusted-skill indicator.

Acceptance Criteria — Untrusted-Skill Indicator (Given/When/Then)

  • AC-STS-001 (Text mode): Given a user-enrolled skill matches an artifact task in text mode, when the reply renders, then a persistent indicator naming the skill is visible in the shell at answer time without opening any log or menu, and the reply's transcript message permanently carries the unverified-skill badge.
  • AC-STS-002 (Voice-only turn): Given a user-enrolled skill matches an artifact task on a voice-only turn, when the handoff is spoken, then the indicator is visible on the session (conversation) screen at answer time, and the turn's entry in the transcript view permanently carries the badge.
  • AC-STS-003 (Curated skill): Given a curated skill matches an artifact task, when the reply is delivered, then no untrusted-skill indicator is shown, and the §12 provider indicator is unaffected.
  • AC-STS-004 (Oversize skill — nothing injected, nothing indicated): Given an enrolled skill whose SKILL.md exceeds SKILL_MAX_INJECTED_BYTES, when it is the highest-confidence match for an artifact task, then the router refuses injection, emits router.skill.oversize, the task runs as if no skill matched, and no untrusted-skill indicator is displayed.
