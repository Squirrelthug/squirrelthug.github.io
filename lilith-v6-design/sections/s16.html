Data Layer
16UCL TelemetryComplete▶

The Universal Communication Log is an encrypted SQLCipher event ledger with one required log_event() call at every mutation point and L2 summaries as the only LLM-readable telemetry surface.

  • Schema: ucl_events(id TEXT PRIMARY KEY, event_type TEXT NOT NULL, payload JSON NOT NULL, timestamp REAL NOT NULL, session_id TEXT); id is UUIDv7 and timestamp is UTC Unix seconds with millisecond precision.
  • Event namespaces: llm.*, tool.*, voice.*, router.*, context.*, sync.*, user.*, memory.*, error.*, onboarding.*, narrative.*, and security.* (rekey, relock, and unlock lifecycle events defined in §02/§06; payloads carry phase, database name, and durations only — never key material).
  • Function: lilith.telemetry.ucl.log_event(event_type: str, payload: dict) -> str writes the event and returns the UUIDv7 event id.
  • Write rule: Every write/mutation path calls log_event() at the actual mutation site, including failures; wrappers are not sufficient for done criteria.
  • Sanitizer Gate: All exception logging must pass through lilith.telemetry.sanitize_exception() before log_event(), plaintext logs, recovery logs, or UI recovery text are written. The sanitizer redacts known secret patterns, including 64-character SQLCipher hex keys, sk-ant- API key prefixes and following token material, Bearer authorization tokens, OAuth refresh tokens, and common provider credential fields. Sanitized output is the only representation allowed to cross the telemetry boundary.
  • error.* Payload Rule: error.* events carry declared fields only: exception type, redacted message, recovery category, component, and non-secret identifiers such as event id or database name. They must never include raw tracebacks, stack frames, locals, reprs of key-manager objects, SQL statements, HTTP headers, request/response bodies, prompts, completions, retrieved context, or user-authored content.
  • Payload Content Boundary: UCL payloads are compact operational facts. Free-text user content and context blocks are stored in conversation_db or the relevant source database, with UCL events referencing them by non-secret id where needed.
  • LLM boundary: LLMs never read ucl_events directly; L1 aggregates telemetry into stats tables, and L2 writes narrative summaries for CWM injection.
  • Search: Create ucl_events_fts as an external-content FTS5 table over serialized payload text for developer/debug search; assert ENABLE_FTS5 from pragma_compile_options at startup and CI.
  • Concurrency: Open ucl_db through sqlcipher3-wheels==0.5.7, set PRAGMA journal_mode=WAL and PRAGMA busy_timeout=5000, and use one connection per thread/job.
CREATE TABLE ucl_events (
  id         TEXT PRIMARY KEY,
  event_type TEXT NOT NULL,
  payload    JSON NOT NULL,
  timestamp  REAL NOT NULL,
  session_id TEXT
);

    CREATE VIRTUAL TABLE ucl_events_fts USING fts5(
  payload_text,
  event_type UNINDEXED,
  content='ucl_events',
  content_rowid='rowid',
  tokenize='unicode61'
);
