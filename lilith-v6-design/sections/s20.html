Application Layer
20Contacts / People AppComplete▶

contacts_db is the encrypted people graph: Google People data syncs read-only into canonical contacts, while Lilith can maintain her own local roster rows with L2 relationship summaries.

  • Database: contacts_db uses SQLCipher with WAL and busy_timeout=5000; all contact PII is encrypted at rest.
  • Google mapping: People API resourceName -> google_id, first names[].displayName -> name, primary emailAddresses[].value -> email, primary phoneNumbers[].value -> phone, first biographies[].value -> notes, etag -> etag, sync time -> synced_at.
  • Lilith roster: Contacts created by Lilith/manual entry set google_id=NULL, etag=NULL, and are never written back to Google in v6 v1.
  • L1 enhancement: Deduplicate by normalized lowercase email first, then E.164-normalized phone; write canonical merge decisions to contacts L1 tables and preserve source ids.
  • L2 enhancement: contact_l2_summaries.summary answers who this person is, recent interactions from conversation history, and Lilith's local notes; CWM reads only L2 summaries.
  • Tools: contact_lookup(name: str) -> str and contact_context(name: str) -> str, both artifact_only, both returning L2 text rather than raw contact rows.
  • Telemetry: Google sync uses sync.contacts.complete from §19; tools emit tool.call.start and tool.call.complete from §15.
CREATE TABLE contacts (
  id TEXT PRIMARY KEY, google_id TEXT, name TEXT, email TEXT, phone TEXT,
  notes TEXT, etag TEXT, synced_at REAL, updated_at REAL
);

CREATE TABLE contact_l2_summaries (
  id TEXT PRIMARY KEY, contact_id TEXT, summary TEXT, generated_at REAL
);

People API -> contacts -> L1 dedup canonical person -> L2 relationship summary -> artifact tools/CWM
