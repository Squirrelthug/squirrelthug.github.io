Data Layer
19Data Sync PipelineComplete▶

Google sync is read-only, local-first, and incremental: OAuth credentials live only in the OS keychain while Calendar and Contacts data land in encrypted SQLCipher databases.

  • OAuth flow: Use google-auth-oauthlib==1.4.0 with installed-app PKCE loopback via InstalledAppFlow.run_local_server(host="127.0.0.1", port=0); open the system browser, never an embedded WebView.
  • Client packages: Pin google-api-python-client==2.198.0 and google-auth==2.55.1.
  • Scopes: Request only https://www.googleapis.com/auth/calendar.readonly and https://www.googleapis.com/auth/contacts.readonly.
  • Token storage: Store only the Google API offline refresh token under key google_oauth_refresh_token with service name "com.squirrelthug.lilith" (as defined in §02's canonical credentials table). The short-lived access token is cached in process memory only; never store OAuth tokens in DB, env vars, JSON config, or logs.
  • Calendar sync: Store Google nextSyncToken in calendar_db; APScheduler interval every 15 minutes while the app is open; handle HTTP 410 by running a new full sync.
  • Contacts sync: Use People API incremental syncToken plus contact etag values in contacts_db; APScheduler interval every 30 minutes while the app is open.
  • First run: Immediately after OAuth succeeds, enqueue full Calendar and Contacts sync jobs before enabling periodic intervals.
  • Read-only enforcement: No write-back methods are registered, no write scopes are requested, and tool definitions expose no Google mutation operations in v6 v1.
  • Calendar/Address Context Processing: To prevent physical address details from being sent to cloud providers and to optimize token consumption, calendar events with location data are pre-processed. A local tool call (e.g., maps/routing API lookup) runs deterministically to translate raw destination addresses into relative plain-text context (e.g., "~45 min northeast of home, typical traffic; alternate route +20 min") before CWM ingestion. This exemplifies the pipeline pattern: raw structured data → tool-processed plain-text context.
  • Telemetry: Emit sync.calendar.start, sync.calendar.complete (items_synced, sync_token), sync.contacts.start, and sync.contacts.complete (items_synced).
Connect Google
  -> system browser PKCE loopback
  -> keyring: google_oauth_refresh_token (service: "com.squirrelthug.lilith")
  -> full calendar sync -> calendar_db.nextSyncToken
  -> full contacts sync -> contacts_db.syncToken + etags
  -> APScheduler intervals: calendar 15m, contacts 30m
  -> L1/L2 enhancement queue
