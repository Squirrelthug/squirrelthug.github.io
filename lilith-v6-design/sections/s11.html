Voice Pipeline
11Text-to-Speech (TTS)Complete▶

Lilith v6 uses Kokoro ONNX for local CPU text-to-speech on every hardware tier, with streaming synthesis into a callback-driven output stream so first audio starts within 500 ms.

  • Package pin: kokoro-onnx==0.5.0 with onnxruntime==1.23.2 and sounddevice==0.5.5; Kokoro model and code are Apache 2.0 and must be listed in licenses/.
  • Voice: af_bella, target speaking rate 135 WPM, mono float32 PCM output.
  • Backend: CPU-only ONNX Runtime provider for Tier 0, Tier 1, and Tier 2; TTS never consumes GPU VRAM reserved for local LLM inference.
  • Latency target: voice.tts.first_chunk must be emitted within 500 ms of voice.tts.start; synthesize by sentence/clause and enqueue the first playable PCM chunk as soon as Kokoro yields it.
  • Cloud-path input gate (Fool's NC-4): On cloud-provider turns, text reaches the sentence/clause chunker only after the §14 reverse-substitution pass: the stream filter holds any open partial tag candidate at a chunk tail (a partial <…> pattern is never released) until it resolves as a tag or is proven not-a-tag — a bounded hold of at most one 16-character candidate per §14's partial-tag hold rule. TTS therefore never receives, and never speaks, a literal or partial anonymous tag; unmapped tags arrive already replaced by §14's neutral placeholders. The 500 ms voice.tts.first_chunk target is measured from voice.tts.start and is unaffected by this upstream hold, whose cost is accounted in §13's conversational budget and measured by the Experiment-1 tokenization on/off delta.
  • Playback: Use sounddevice.OutputStream(channels=1, samplerate=24000, blocksize=1024); the PortAudio callback drains a bounded PCM queue, pads underruns with silence, and computes RMS for orb animation.
  • Telemetry: Emit voice.tts.start (voice, chars), voice.tts.first_chunk (latency_ms, frames), and voice.tts.complete (duration_ms, chunks, success).
