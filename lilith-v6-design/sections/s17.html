17Enhancement Layers (L1/L2)Complete▶

Every LLM-visible data domain flows through background L1 aggregation followed by L2 narrative summarization, with L1 jobs prioritized and raw tables never exposed to CWM.

  • Scheduler: APScheduler==3.11.3 BackgroundScheduler handles periodic timers; a small internal priority queue handles triggered enhancement jobs where L1 must run before L2.
  • L1 job: Triggered by DB write UCL events and polled every 2 s with an APScheduler interval trigger; idempotent, no LLM calls, writes normalized/aggregated *_l1 tables.
  • L2 job: Enqueued only after the matching L1 job succeeds. For domains that contain untrusted third-party or externally-sourced text (specifically calendar events and contacts sync), the L2 job strictly uses template-based (non-LLM) generation in v6 v1 to mitigate prompt injection risks, extending the deterministic template pattern of §21. Other domains (like memory) may use templates or an LLM in artifact/background mode. Writes human-readable *_l2_summaries rows for CWM.
  • Priority: Queue priorities are 0=L1, 10=L2, 20=maintenance; L2 for a DB/domain is blocked until the latest L1 watermark is at or beyond the source write timestamp.
  • Intent-triggered refresh (§14 staleness gate): CWM may request a targeted refresh for a single domain when a stale or absent block matches turn intent. The request enqueues that domain's jobs at the head of their existing priority classes (L1 at 0 before L2 at 10 — ordering and L1-watermark rules unchanged), preceded by an incremental source sync (§19) when the source watermark is stale and the domain supports automated sync. Every domain registered with the pipeline declares a refresh_capability: sync_and_enhance (calendar, contacts — sync then L1/L2), enhance_only (memory, telemetry-derived tool context — L1/L2 recompute only), or manual_source (reserved for future manual-import domains such as the parked finance statement import — requires user action). manual_source domains are never auto-refreshed; CWM discloses absence with status="source_unsupported" instead. Refresh jobs obey the same overlap controls (coalesce=True, max_instances=1); a refresh that outlives the requesting turn's §14 lane budget keeps running in the background so the next turn reads fresh summaries. CWM emits the context.refresh.* events (§14); the jobs themselves emit the existing sync.l1.complete/sync.l2.complete.
  • Database access: Every job opens its own keyed SQLCipher connection with pathlib.Path, sets PRAGMA journal_mode=WAL and PRAGMA busy_timeout=5000, runs short transactions, then closes.
  • Overlap control: Scheduler defaults are coalesce=True, max_instances=1, misfire_grace_time=60; stale running jobs reset to queued on startup.
  • CWM freshness: §14 thresholds apply to L2 summaries: tool context 5m, calendar/contact entity context 30m, memory recall 24h, personal truths 7d, system identity 24h.
  • Telemetry: Emit sync.l1.complete (db_name, rows_processed, watermark) and sync.l2.complete (db_name, summaries_written, source_watermark).
DB write -> log_event(...) -> enhancement queue
  priority 0: L1 aggregate/normalize -> *_l1 tables -> sync.l1.complete
  priority 10: L2 summarize/narrate  -> *_l2_summaries -> sync.l2.complete
  CWM reads only fresh *_l2_summaries, never source tables or raw UCL rows
