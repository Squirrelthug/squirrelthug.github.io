Architecture decisions already locked

  • ✓ Frontend framework: PySide6 6.11.1 (LGPL v3) + ModernGL 5.x (MIT) for the orb via QOpenGLWidget. Qt Quick 3D dropped (GPLv3-only, incompatible with closed-source distribution).
  • ✓ Voice is the default, non-negotiable at the Tier 0 minimum: STT (Whisper) + TTS (Kokoro) run on every supported machine. The desktop chat screen also accepts typed input at any time, with TTS available on demand per message rather than forced — see §13, §22.
  • ✓ All databases: SQLCipher from first migration. No plaintext SQLite anywhere.
  • ✓ All credentials: OS keychain via python-keyring. Never in .env, never in config files.
  • ✓ External APIs (v6 v1): Read-only. Lilith manages her own calendar and contact roster separately.
  • ✓ Two-mode router architecture: Conversational vs Artifact (acknowledge → background → handoff). The two-mode split itself is locked; its tuning numbers (≤50 output tokens, ≤3 s to audio, ≤1200 context tokens) are v6 v1 working hypotheses to be validated in Milestone 1, not immutable constants — see §13.
  • ✓ LLM access: L1/L2 enhanced data only. Raw DB rows never enter the context window.
  • ✓ BYOK: User-provided API keys. No managed cloud inference from Lilith.
  • ✓ Path handling: pathlib.Path everywhere. No string path concatenation, no hardcoded separators.
  • ✓ Distribution model: Lilith v6 is free, closed-source, no license key, no activation. Wide distribution is the goal. Revenue comes from a future cloud sync subscription (Obsidian model). v6 v1 has no paid features — users bring their own API keys and their own Google account. No piracy surface to protect against.
  • ✓ Memory recall (v6 v1): Recency-first + FTS5 keyword search. No local embeddings or vector search in v6 v1 — that is a future phase. See §18 for full spec.
  • ✓ Custodian Model: All internal data (SQLCipher databases, salts, config, logs, cache, models, and skills) lives in a single OS-standard application directory (APP_INTERNAL_DIR) with strict POSIX 0700/0600 permissions. The user's primary files, notes, and documents (including external Obsidian note vaults) are never copied to Lilith's storage; she acts as a custodian, maintaining paths/pointers and indexing summaries. Accumulated history (UCL, memory, conversation DBs) is portable via Lilith's backup/restore utility. See §04, §29.
