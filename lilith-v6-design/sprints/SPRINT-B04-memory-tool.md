## Goal

Lilith remembers. Conversation turns persist, and the one Milestone-1 tool — `recall_memory` — retrieves them through the tool runner with its spoken narratives. At sprint end: `conversation_db` has the §22 `sessions` and `turns` tables and an FTS5 index over `turns`; every CH-03 pipeline turn (user and assistant) is written to them and indexed; `lilith/tools/` holds the single `recall_memory.yaml` contract parsed with `yaml.safe_load`; the runner executes exactly that one tool; a recall query is classified artifact, runs `recall_memory` (recency + FTS5, per the §18 Recall mechanism v1) against real stored dictations, and speaks acknowledge → handoff narratives in order, or the failure narrative on a forced error — with narrative text delivered through a sink seam (live TTS attachment is CH-06). No embedding, vector, `memory_db`, `memory_embeddings`, L1/L2 or second tool exists.

### Definition of Done (verbatim from `BUILD_GUIDE.md` §5, CH-04)

- [ ] Conversation turns from the CH-03 pipeline persist to `turns`/`sessions` and are FTS5-indexed.
- [ ] A recall query routes to the artifact lane, executes `recall_memory`, and returns a response built from real stored dictations, with acknowledge/handoff narratives firing in order and the failure narrative firing on a forced error.
- [ ] `pip`/lock-file audit: no vector or embedding dependency present.
- [ ] Integration test covers dictate → persist → recall round-trip per §08.

### [B04-03] Recall retrieval: recency + FTS5 (data layer)

**Law:** `../sections/s18.html` (`Recall mechanism`, `Telemetry:`, `Recall Roadmap`), `../BUILD_SEQUENCING.md` §2.1 (§17 row; §18 row), `../sections/s08.html` (`No-DB-Mocking Policy:`, `UCL Telemetry Assertions:`)
